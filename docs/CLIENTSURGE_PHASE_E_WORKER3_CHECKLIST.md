## Global Review Checks

- White-dominant workspace remains intact.
- Navy is structural and not used as a generic status color.
- Commerce Blue is not used for non-commerce actions.
- Cards are flat, thin-bordered, and not nested inside other cards.
- Critical state and next action appear before passive reference material.
- Mobile order prioritizes blockers, actions, source truth, and recovery.
- Long route names and recovery paths do not create horizontal overflow.
- State meaning does not rely on color alone.
- Unknown, unavailable, estimated, reported, and permission-restricted states are visually distinct from verified/healthy states.

## Accessibility Checks

- One `main` landmark is present per route.
- H1 matches the route purpose.
- Active route uses `aria-current="page"`.
- Fixture notice uses polite status semantics.
- All interactive controls are keyboard reachable.
- Focus is visible when tabbing.
- Focus order starts at skip link, then route navigation, then page content.
- Recovery links have meaningful destination text.
- Touch targets remain usable at `390` and `375` widths.
- Content reflows at 200% zoom without horizontal overflow.
- Reduced-motion mode does not require running animations.
- Contrast should be manually reviewed against WCAG 2.2 AA.

## Route-Specific Review

### Onboarding

- Customer-facing copy uses "Activate Your Business" language.
- Activation progress does not imply AI readiness before evidence.
- Payment completion remains fixture-only and not live billing proof.
- First business result is unavailable until delivery evidence exists.
- Blocked connection state names owner, impact, preserved progress, and recovery path.

### Home Entry

- Returning-user view answers current status, recent activity, pending actions, and recommendations quickly.
- Incomplete setup and needs-attention states stay above passive snapshot material.
- Partial coverage is clear and not treated as zero.
- Recommendations include source, owner, lifecycle, and impact truth.

### Trial

- Trial language avoids false urgency.
- Days remaining does not hide activation limitations.
- Activated features and unused features are separated.
- Expired trial state preserves setup and explains recovery.
- Upgrade path does not imply conversion without billing proof.

### Subscription

- Current plan is labelled as fixture-backed.
- Upgrade flow follows Review Change, Confirm, Apply, Show Result.
- Downgrade protection shows features lost, current usage, impact, and confirmation.
- Apply/result states remain unavailable until approved billing mutation exists.
- Commerce styling is reserved for true commercial commitment.

### Search

- Search categories cover customers, leads, conversations, AI workers, timeline events, settings, billing, and documents.
- Restricted content does not leak title, snippet, count, or autocomplete content.
- Recent, empty, partial, no-permission, and error states are visible.
- Keyboard model for Command K / Ctrl K, arrows, Enter, Escape, and focus restore is clear.

### Command Menu

- Safe navigation commands are separated from destructive actions.
- Open Customer, Open AI Worker, Create Message, View Billing, Open Settings, Reconnect Integration, and Search Everything are represented.
- Permission-restricted commands explain role or setup requirements.
- Mobile command launcher remains discoverable and reachable.

### Notifications

- Notification rows communicate title, what happened, why it matters, impact, owner, action, destination, and status.
- Unread, read, resolved, stale, expired, permission-restricted, and unavailable states are visible.
- Critical examples translate technical issues into business impact.
- Badge semantics mean unread actionable notifications only.

### Help

- Help sections cover getting started, AI workforce, website, billing, integrations, troubleshooting, and best practices.
- Contextual help appears where the customer needs it.
- Troubleshooting steps name owner, consequence, preserved work, and escalation path.
- Restricted help does not leak protected billing/security details.

### Incidents

- Operational does not mean "no evidence."
- Degraded and partial-impact states put business consequence before technical detail.
- Major incident state names affected systems, current action, next update, and history.
- Resolved state preserves incident history.
- Maintenance language is calm and specific.

### Launch Readiness

- Ten Phase E systems are listed in the launch matrix.
- Six viewport widths are visible.
- Keyboard, focus, ARIA, screen-reader, reduced-motion, touch-target, contrast, and 200% zoom checks are represented.
- Truth rules remain explicit:
  - Unknown is not healthy
  - Estimated is not verified
  - Sent is not delivered
  - No data is not zero
  - Configured is not working
  - Connected is not healthy
